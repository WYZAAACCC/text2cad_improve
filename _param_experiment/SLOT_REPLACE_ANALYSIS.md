# 榫槽 prompt 替换兼容性分析 — 当前参数化生成 vs server 旧 prompt

> 日期：2026-08-03
> 目的：检查当前参数化生成的榫槽（5点/齿结构）能否直接替换 server 旧 prompt 生成的榫槽（3点/齿结构）

---

## 一、结论（摘要）

**不能直接替换**。原因：

1. **格式兼容**（add_polyline 的 `[{"x_mm":..,"y_mm":..}]` 点数组）✓
2. **结构不兼容**：旧 prompt 每齿 3 点 + 水平颈部平台；当前参数化每齿 5 点 + 斜线齿根
3. **fillet_sketch 顶点索引失效（致命）**：旧索引 `[1,5,9,12,13,16,20,24]` 等绑定旧 26 点结构，替换后作用到错误顶点

**替换方案**：必须同步更新 fillet_sketch 的 `at_vertex_index` 规则（或让 fillet 索引基于新结构参数化重算）。

---

| 项 | server 旧 prompt | 当前参数化 | 兼容 |
|----|----------------|-----------|------|
| 点格式 | `{"x_mm":..,"y_mm":..}` | 相同 | ✓ |
| 点数（2齿） | 26 | 26 | ✓（巧合相同） |

## 四、fillet_sketch 索引失效分析（致命）

### server 旧 fillet 规则（绑定旧 26 点结构）
```
lobe_tops  radius=1  at_vertex_index=[3, 7, 11, 14, 18, 22]   # 齿顶凸台
flanks     radius=0  at_vertex_index=[2,4,6,8,10,15,17,19,21,23]  # 斜面
neck_root  radius=0  at_vertex_index=[1,5,9,12,13,16,20,24]   # 颈部/根部
```

### 若直接替换为新 26 点结构
| 索引 | 旧含义 | 新结构中该索引指向 | 是否仍正确 |
|------|--------|-------------------|-----------|
| 3 | 齿1顶部 | 齿0齿顶平台端 | 恰好仍接近 ✓ |
| 7 | 齿2顶部 | 齿1齿顶平台端 | ✓ |
| 11 | 槽底 | 槽底平台端 | ✗（应倒槽底，非平台端） |
| 1 | 颈部1 | 齿0外斜面起点 | ✗（颈部起点 vs 齿根斜线） |
| 5 | 颈部2 | 齿0连接线端 | ✗（语义不同） |
| 9 | 颈部3 | 齿1连接线端 | ✗ |
| 12,13 | 根部 | 根部/下侧根部 | ✗（新结构根部=12） |

**结论**：约 50% 索引语义错位，直接替换会导致倒角作用在错误顶点（榫槽形状错误）。

---

## 五、替换方案（如需替换）

### 方案 A：同步重算 fillet 索引
新结构（5点/齿，2齿）正确的 fillet 目标：
- **齿顶圆角**（lobe_tops）：齿顶平台两端 → 索引 `[2,3]`（齿0）、`[6,7]`（齿1）…即每齿 `[4i+2, 4i+3]`
- **齿根圆角**（neck_root）：齿根斜线点 → `[1]`（颈部1）、`[4]`（齿0内斜面端）、`[8]`（齿1内斜面端）、`[12]`（根部）
- **斜面圆角**（flanks）：外斜面顶/内斜面端 → `[2,4,6,8,10,12]` 等

### 方案 B：让 fillet 索引参数化
在参数化 IR 中，用 `construction_role`（外斜面顶/齿顶平台/内斜面端/连接线端/根部）代替裸索引，由执行端按实际点数计算索引。最稳健。

### 方案 C：轮廓内嵌圆角
把圆角直接并入轮廓点生成（几何生成时加圆弧段），完全移除 fillet_sketch 依赖。最彻底，但改变 sketch_profile 方言语义。

## 六、其他差异（替换时需注意）

| 项 | server 旧 | 当前参数化 | 影响 |
|----|----------|-----------|------|
| 齿高方向 | 等高（齿1=齿2=5mm） | 可参数化（递减/递增） | 需确认目标方向 |
| 颈部半宽 | 恒定 2mm | 斜线递减 2.6→1.8 | 形状变化 |
| 底部 | y=3, 槽底平台1mm | y=4, 槽底平台2mm | 形状变化 |
| 槽深 | 24mm | 可参数化 | 需确认 |
| 精度 | 整数（LLM 取整） | 3 位小数 | 更精确 |

---

## 七、结论

- **格式层面**：可直接替换（add_polyline 接受任意点数组）
- **几何/结构层面**：**不能直接替换**——每点语义不同，fillet_sketch 索引约 50% 错位
- **若替换**：必须同步更新 fillet_sketch 索引（方案 A/B/C），并确认齿高方向、颈部、底部等参数目标

**建议**：若目标是让 server 生成参数化榫槽，应采用"方案 B（construction_role 语义索引）"——fillet 索引不绑定点数，由执行端按角色解析，这样无论 LLM 输出何种点数结构都能正确倒角。
