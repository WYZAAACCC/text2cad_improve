⚠ 更正声明 · 2026-09-15 · 本文档部分结论已被证伪，请勿引用

创新点 A 不成立。「把应力场/梯度与参数化特征联系起来」在古典优化界已于 1994 年启动、2012 年成熟，并且已用于涡轮：Verstraete, Müller & Müller（ASME Turbo Expo 2017, GT2017-65005）以 max von Mises 为目标对 CAD 特征参数求伴随梯度，结论直接表述为「extend the back plate near the radial center」。Robinson, Armstrong & Chua（SMO 46(3), 2012）更早就用 adjoint 灵敏度图在四种特征类型里选收益最大的那个。

LLM 侧也已有人做。FRAME（OpenReview 2TdYc5V4jU）用 VLM 读 FEA 云图 → 识别应力集中 → 提出具名几何修改（如「increase fillet radius」）→ 生成脚本更新 CSG → 重算。这正是本文档「创新点 A」描述的工作流。

创新点 C 的论证基础塌了。同构不变性检验抓不到那个 53% 的选面错误——两条榫齿带半径差 70 mm（202–214 vs 281–295），没有任何对称或重编号能把一条映射成另一条。该错误是语义/知识错误（D27 模型里没有叶根），不是 shortcut。另，四类「同构变换」中单位制切换不是不变性而是协变性，属概念错误。

横向对比与创新点阐释 · 2026-09-15

空的那一层。

这份文档回答三个问题：别人做到哪了、空白具体在哪、 以及为什么我们选的这个方向既没人做过、又一定做得成。 全部结论都有出处，关键处附原文引语。

论点问题不在"有没有闭环"，在"闭环里的反馈有多细"

2025–2026 年，"让 LLM 把 CAD 和 CAE 串起来，根据仿真结果改设计"这件事已经被至少十项工作做过。 所以第一件要说清的事是：我们不能靠"做了闭环"来立论。

但把这十项工作放在一起看，会发现一个规律——它们对**反馈信号**的使用方式，几乎全部停在最粗的两档： 要么只知道"跑通了没有"，要么只知道"最大应力是多少"。而越往细走，人越少，到"梯度"这一档， 一个人都没有。

反馈的语义分辨率，决定了闭环能不能收敛。
而分辨率不能再靠"让模型多看图"来提高。

把反馈按分辨率排成五档，就会发现：L0 和 L1 挤满了人，L2 是经典力学几十年的地盘， L3 有人试过并且失败了，L4 完全空着。 而 L3 的失败方式很说明问题——不是模型不够强，是它被要求从一张彩色云图里， 反推一个它根本算不出来的量。

§2 不要创新的地方已经堵死的三档

先划掉不能去的地方，剩下的才是方向。每一条都有实测证据。

L0 / L1 不是"还可以做得更好"，是已经做到了天花板

最直接的证据来自一篇专门做的对照实验（arXiv:2609.03718）。它在信息量与修复预算固定的条件下， 比较"一个通用编码 harness"和"精心设计的多 agent 专用系统"：

对照项结果含义
通用单 agent harness vs 专用多 agent96.4% vs 88.2%多 agent 编排没有优势
execution-feedback repair71.8% → 96.4%真正的驱动力是"读日志改代码"
scripted reflection（让 LLM 反思）零增益反思这条路已经走完了
注入 solver tutorials（领域知识）80.9% → 96.4%唯一还有增益的输入是知识

这篇的结论直接点名了领域的缺口： 「多数 CAE 基准只检查生成的代码能不能跑，不检查物理是否正确」。 但它同时说明：在 L0/L1 这一层，"再加一个 agent"或"再让 LLM 反思一轮"已经不出活了。

L2 是经典力学几十年的地盘

"全场 → 网格单元"这一档早就被解决了，只是解决它的人不在 AI 社区： SIMP 的热点检测、经典形状优化、以及 CAD 侧的 feature-mapping optimization（Shannon / Robinson 等，Queen's University Belfast 2023） 与 Parametric Design Velocities——后者已经把 adjoint 表面灵敏度与 "CAD 参数变化引起的边界法向移动"链接起来，直接给出目标函数对 CAD 参数的梯度。

在这三档里声称创新，会被审稿人用几十年文献压掉。 但它们的存在有一个反过来的用处——见 §3。

还有三条看起来诱人、实际已经死掉的路

✕"再多迭代几轮就好了"

Frontier-Eng 在 47 个真实工程任务上测出双重幂律衰减：改进频率按 t⁻¹（R² = 0.84）、 改进幅度按 k⁻¹ 衰减，中位数每任务只有 7 次改善，50–100 轮后趋零。 Physics-in-the-Loop 更直白地自陈：「迭代越多，结果越不稳定」， 并要求未来工作去研究「何时判定一个 CAD 设计已不可恢复」。 迭代次数不是免费资源，它有上限。

✕"让 LLM 看应力云图，自己提设计建议"

IterSIMP-σ（2605.19110）正是这么做的——多模态 LLM 读密度图 + von Mises 渲染图， 提出"空间干预"（软密度种子）。结果：几何均值低 1.9%，但不显著（W = 33, 双侧 p = 0.382）， 而确定性 exact-hotspot 启发式打平。作者的结论原话是： 「尚不能作为 LLM 视觉推理改善应力约束优化的证据」。 给模型更多图，不会让它更懂力学。

✕"我们的 agent 省了仿真次数"

这个主张有两个硬对照必须打赢。一是 When Is an LLM Worth It for HPO?（2606.21641）： budget-matched 条件下给经典搜索同样的 warm-start，LLM 提议不带来任何 sample efficiency 优势 （TPE/GP-BO 约 12 次评估后追平，40 次反超）。二是 SimulCost（2603.20253，ICML）： LLM agent 比传统 scanning 慢 1.5–2.5×。 省算力这条路上，LLM 目前是输的。

把 §2 的结论合起来

L0/L1 堵死、L2 是老地盘、三条诱人路径都有实测反例。 剩下的空间非常小，但也因此非常清楚——只能往反馈的语义分辨率上走。

§3 空白两篇自己承认做不到的工作

这是本次调研最有价值的部分：空白不是我们推断出来的，是别人写在正文里的。

3.1 L4 的空白：梯度就在那里，只是没人把它递过去

先看一句原文。IterSIMP-σ 的作者在 §7.1 主动交代了他们架构上的选择以及它的代价：

"This is a deliberate architectural choice, not an equivalence claim, and it has concrete consequences. The SIMP density update receives no gradient information about the stress field: sensitivities ∂σvm/∂ρe are never computed, and the optimality-criteria update drives densities toward compliance reduction without direct knowledge of where stress concentrations are forming. In classical stress-constrained formulations—P-norm penalty, augmented Lagrangian, or q-p-relaxation— the stress constraint enters the Lagrangian directly, and adjoint analysis provides element-wise stress sensitivity to guide the density update."

IterSIMP-σ, arXiv:2605.19110 §7.1

这段话的意思是：经典方法本来就会算这个梯度，而我们故意没算，因为我们要让 LLM 来做决策。 于是问题来了——梯度去哪了？

第二句引语来自 LLM-IDA——十项工作里架构最完整的一篇（L0/L1/L2 三层、PyAnsys、NSGA-II）。 在摩托车车架案例中，作者写道：

"It is important to note that to simulate diverse industrial design scenarios, the input is not a 3D modeling code, but a completed 3D model. This implies that the LLM-IDA cannot read the coordinates of the load and constraint points. Therefore, a manual step is required to select the load points based on LLM-IDA simulation suggestions… If future research enables the identification and selection of the simulation load and constraint points, LLM-IDA can achieve full-process automation in complex scenarios."

§4 创新点三个位置，以及为什么是我们

每一项按同一结构展开：是什么 → 别人做到哪了 → 为什么这算创新 → 为什么选它 → 我们已有的证据。

创新点 A · L4

把特征灵敏度递进智能体的决策上下文

不再让模型从云图里猜"哪里该改"，而是直接告诉它"目标对每个命名特征参数的灵敏度是多少"。

是什么

把仿真侧已经算出来的 adjoint 灵敏度（或 CAD 侧的 feature-mapping / Parametric Design Velocities 梯度）， 整理成"对某个命名特征参数的灵敏度"的形式，作为工具返回值交给智能体。 智能体拿到的不是一张图，而是一个排序过的、带单位的、指向具体特征参数的清单。

别人做到哪了

没有人把导数场送进 LLM。三种现有模式全部止步于原函数场： LLM 编排梯度求解器（梯度在求解器内闭环）、LLM 只看标量或渲染图（只有 primal field）、 或数值融合但决策者不是 LLM。IterSIMP-σ 的作者甚至主动写明"我们故意不算这个梯度"。

一个必须知道的现代威胁：ShapeBench（2605.20763，Stanford，103 个 ASO 任务） 已经把 E.1 Adjoint (IPOPT) 作为一个 baseline，与三个 LLM 优化器在同一批任务、 同一预算下头对头对打。所以"adjoint 对比 LLM"这件事本身已经有人做了。

但它做的不是同一件事：它把 adjoint 当作一个独立的优化基线来跑， 并没有把梯度放进 LLM 的上下文。两者是"用梯度代替 LLM"和"把梯度交给 LLM"的区别。

为什么这算创新

有三层理由，从弱到强：

  • 它是唯一"两侧成熟、只缺接口"的位置。 不是要发明新的梯度算法，也不是要发明新的 CAD 参数化——两边的工具都在，只是从没接上。 这类创新风险最低、最容易做出对比实验。
  • 它绕开了已被证伪的那条路。 IterSIMP-σ 的 p = 0.382 说明"让模型从图里反推干预"打不过确定性启发式。 原因很可能是：那个量根本不是从图里能推出来的。 梯度是局部导数信息，云图是全局原函数信息——要模型从后者反推前者， 等于要求它做一次它没有工具的积分逆运算。 给梯度，是把问题从"推断"降级为"读取"。
  • 它把 LLM 放回了它擅长的地方。 两篇独立工作都测出 LLM 在数值优化上不占优（HPO 对照、SimulCost）。 但语义工作——"这个灵敏度是挂在哪个特征上的""这个特征改动会不会破坏装配"—— 恰恰是 LLM 能做好而梯度法做不了的。灵敏度给数值方向，LLM 给语义约束， 这是分工而不是竞争。
为什么选它（可行性）

因为我们的系统有一个别人没有的东西：命名的、跨 revision 稳定的特征参数。 这不是巧合——"σ 对 rim_junc 圆角半径的灵敏度"这句话要成立， 前提就是 rim_junc 在两次迭代之间是同一个实体。 没有这个前提，梯度算出来了也无处可挂（挂到"第 47 号面"上，下一次迭代这个编号就变了）。

换句话说：这条路别人不是没想到，是他们的身份系统撑不住。

创新点 B · 反馈可信度

把"这条反馈是不是假象"做成环路的门

现有系统会把网格改善、载荷施加伪影、绑定缺失当成设计改善记下来。我们要在它进入接受准则之前拦住。

是什么

在"仿真结果 → 设计决策"这条边上，插入一个可信度判定： 这条反馈是真实的设计改善，还是数值假象？ 判据包括常应力分片试验、网格收敛检查、正负对照。 只有通过判定的反馈才有资格驱动设计。

别人做到哪了

假象是被记录在案的，但没人拦它。Hephaestus-CCX 对九例 pass-flip 做了归因分析， 四类修复里有两类是假象：

  • 「mesh-sensitive geometry simplification」—— 把加载路径简化、网格随之变好，被记为设计改善。
  • 「checker-contract repairs」——物理本来就对， 只是 metric alias / mass field / selector binding 缺失导致判失败。

网格本身也在掩盖问题。IterSIMP-σ §7.3 自陈：「基准问题用的网格相对粗糙（1,600–8,000 单元）…… 在粗分辨率下，应力集中被网格本身部分抹平，可能低估了应力约束的难度」。 而它 §7.5 给出的下一步不是调 prompt，是"固定体积的 3D 重算与网格细化检查"。

验证这一侧也不是没人做，但做的不是这件事。2026 有一个成型的子领域做"物理是否正确"： PDE-Grounded Intent Verification 验的是设置的方程对不对（220 例中 39–40% 能跑但解错物理）； PHACT 验的是可行性；PA-SciML / PhysVEC 验的是场是否满足守恒律与对称性。 它们全都是一次性验一个产物，没有一个把判定做成迭代环路里的门。

为什么这算创新

因为空白的形状很精确：

没有任何工作把网格收敛 / 离散化检查作为 accept/reject 门放进 agent 环。

检索是零命中的——没有一篇用"同一网格"或"网格收敛性研究"作为改进验证的协议。 ShapeBench 有诊断套件能诊断出 surrogate exploitation （逐字证据：DrivAerStar 的 20 个参数里 13 个在所有方法的收敛最优解上都被推到边界， 「indicating that this convergence pattern is a landscape property of the surrogate」）， 但它不把诊断结果作为门。 唯一认真处理求解器可信度的是 Luo et al.（OpenSeesPy 误差 <1%、与独立 ANSYS APDL 容差 2–3%）， 但只做到引擎精度层，而且是一次性的，不在迭代里。

更深一层，这件事有理论依据。 有一篇工作论证了：作为 test oracle 的仿真器必须先被认证，它的 verdict 才算保证证据； 而且给出一个反直觉结果——视觉保真度最高的模型，在闭环 verdict 的可靠性上排名更低。 另一份可信度阶梯把它们分级：Tier III（数值仿真与守恒律） 「不真正解题就很难伪造」，而 Tier V（学习型 verifier / 代理奖励）会撞上 reliability cliff，且「代理模型自己的置信度，对特定实例没有任何证明力」。 另有报告指出同模型 verifier 反而让任务成功率回退 8.4 个百分点。

为什么选它

因为我们已经在做这件事，而且做出过一次否定自己的结果。 这是最难伪造的一种资历：不是"我们设计了一个验证器"，而是"我们的验证器推翻了我们自己的头条数字"。

而且它有一个 20 年历史的理论归宿：这正是 VV&UQ 里的 solution verification （ASME V&V 20 / Oberkampf），而 PCMM（Sandia 2007，六要素四级，每要素打成熟度/证据强度/相关性三个分） 与 LLM agent 至今没有交集——我专门查过，检索结论是它们「没有专门处理 LLM agent 执行自动可信度评估」。 落在 CMAME 这样既懂力学又懂方法的期刊上，这条线索是加分项。

创新点 C · 新机制

物理同构不变性检验

用"结论在保持物理语义的变换下是否不变"来判据真伪。原理已被证明有效，但没人定义过物理设计的同构变换。

是什么

对智能体给出的结论，施加一组保持物理语义的变换，看结论是否依然成立。 例如："这批面是承力面"——把扇区旋转 k × 6°，这个物理事实不应该变。 如果结论崩了，那它就不是从物理事实得来的，而是从某个偶然特征得来的。

涡轮盘的候选变换集是天然存在、且可以自动生成的：

  • 周期扇区旋转（60 重对称，旋转 k × 6°）
  • 特征重编号（榫槽 1..60 循环重排）
  • 单位制切换（mm-N-s ↔ m-kg-s；代码里已有 mm-N-t-s 的明确约定）
  • 网格节点重排（同一几何、不同编号）
别人做到哪了

原理来自 IPT（Isomorphic Perturbation Testing，2604.15149，DFKI / TU Darmstadt）， 但它做的是逻辑规则域。它发现：

  • 只检查 extensional correctness（给定的那些实例对不对）的验证器， 会主动诱导模型放弃规则学习、转而枚举实例级标签
  • shortcut 率：GPT-5-nano 36.8%、GPT-5-mini-high 8.4%、GPT-4o 与 Ministral 0%
  • 随着任务复杂度与推理算力上升而上升——算力越多，越会钻空子
  • 对照训练证明是因果而非相关：extensional 验证诱导 shortcut，isomorphic 验证消除 shortcut

而没有人定义过"物理设计的同构变换"是什么。这是一个机制级空白。

为什么这算创新，以及为什么它能解释我们已有的现象

我们的选面 agent 用的是纯 extensional 验证器：它自己写下判据， harness 拿这份判据去校验它的提交，check_criterion 每次都通过。 实测 34 次：正确 18（53%）、选错 8、未提交 8。 当时我只能说"这是自洽而非正确"——现在有了因果解释。

更关键的是，同构检验能精确定位那个错误： 主导错误（8 次里 7 次）是同一个槽、同一方位角、半径差 70 mm 的两条榫齿带。 这两条带在所有几何量上无法区分，在扇区旋转和特征重编号下也不可区分—— 而 agent 的判据把它们区分了。 也就是说：那条判据本身就是一个 shortcut。 同构检验会直接把它抓出来，而不需要人去看。

而且它回应了一个理论挑战。 有工作论证：没有任何固定的 reward function 能在策略能力增长时保持有效， 验证必须与生成器共同演化。这对"agent 自己写判据"是一个直接威胁—— 判据若静态，会被 agent 追上并钻空子。 同构不变性是不依赖判据内容的独立检验，因此不受这条威胁影响。

为什么选它（投入产出比最高）

实现成本低——复用已有的对称性测量、role 重映射、单位换算，不需要新算法。 而它给出的不是一个新指标，是一个可否证、可预测的检验： 要么结论在变换下存活，要么它就是个 shortcut，没有解释空间。 这是三个创新点里最可能在审稿中被认作"新方法"的一块，也是最便宜的一块。

溯源锚定的跨 revision 实体身份

它不是三个创新点之一——它是那三个能成立的前提条件。

A 需要它：灵敏度必须挂在命名特征上，"σ 对 rim_junc 圆角半径的灵敏度" 要求 rim_junc 跨迭代是同一个实体。
B 需要它：可信度判定要锚到具体实体上，"这条面绑定的结果不可引用"要说得清是哪条面。
C 需要它：同构变换里的"特征重编号"本身就是身份操作。

而 COMSOL-MCP（Neurocomputing 2026，76 个工具的多物理场 agent 接口）在 future work 里 写的就是 spatial grounding + topology-aware entity selection， 并给出痛点原话：「语法合法的 API 调用仍可能生成物理上无效的模型」。

为什么这不是"我们也做了个持久命名"

Kerf、CADIR、MusubiCAD 都做了持久化。但三条经典路线各有硬伤： TNaming 跨布尔脆弱（FreeCAD 1.0 仍部分失效）、 几何哈希在对称件上歧义（Kerf 自陈在齿轮齿、螺栓孔阵列上碰撞）、 occurrence path 只是快照不跨重建。 而枞树形榫槽的 60 重对称，正是几何哈希路线的死穴。

§6 边界必须如实说出的限制

  • 载荷是合成的。当前为 10 kN/槽的烟测值，状态 synthetic_or_unconfirmed_pipeline_validation。 写法上应把贡献定位为方法而非该盘的设计结论，并说明载荷可替换。
  • 选面 53%。这不是可以藏的数字，而恰好是创新点 C 的主体。 要把它从"系统缺陷"转成"被测量的现象 + 由此得出的机制性解释"。
  • 闭环尚未实现。仓库里有 8 个修复环（几何有效性、求解收敛、网格质量）、 有设计探索、有能产出丰富指标的仿真——但没有任何一行代码读走仿真结果去改设计参数。 E1 是硬门槛。
  • CFD 侧 LLM 未启用，且 CFD 修复环目前是空转的（写 solver.control.relaxation 而 worker 从不消费该字段，重试与失败 run 逐字节相同）。声称"多物理场"时必须写清。
  • 引用卫生。COSMO-Agent 在 arXiv 上有两个 ID 同标题同摘要（是一篇不是两篇）； Embodied CAD 用的是 CAD 几何内核不是物理求解器； DesAgent 是 closed access、数字中等置信度； 部分文献链接是机构代理镜像，正式稿需换回规范链接。
