## 一、项目目标（论文数据集要求，简略）

- **S 元组**（每个几何样本）= {T 需求文本, P 参数表, Gf Feature Graph, Dg Disk-G-CAD, CCAD 执行序列, MBRep 原生 B-rep, MSTEP, Rquality, Rregen}；**Y 元组** = (Gf, Dg, MCAD, MSTEP, Rq, L 日志)。
- **32 设计族**（20 训练 / 4 验证 / 8 留出）6 类：基础盘 4 / 孔阵列盘 5 / 环槽盘 5 / 标准榫槽盘 8 / 耦合盘 6 / 复杂轮缘盘 4。榫槽模型占有效模型 63.5%。
- **102,400 候选 → 5 级过滤 → 49,920 有效模型 → 217,920 任务**（Gen 149,760 / Edit 24,960 / Repair 30,720 / MCP 12,480）。每 Gen 样本配 SER 七步标注。
- **隔离原则**：设计族、榫槽母型、图哈希、文档哈希、B-rep 指纹五层；同几何模型的 Gen/Edit/Repair/MCP 必须同集合。
- **用户明确**：NL2DiskCAD-Gen 的规范化参数表不需要（Gen 输出为 3 描述 + SER）。

## 二、当前系统全貌

### 2.1 生成层（已 agent 化）

**核心文件**：`app/text-to-cad/server/agentic_l2.py`，环境变量 `AGENTIC_L2=1` 启用（默认走旧单 LLM，`main.py` L2 段 :656 分支）。

```
Agent A 整体设计（LLM）    需求 → AgentDesignPlan（RawGcadDocument 骨架，add_polyline.points 占位
                            + profiles：每个轮廓 {profile_id, kind, params 完整参数集}）
   ↓
Agent B 轮廓实现（LLM）    每类型一个 agent（盘体 disc / 榫槽 slot）：参数 → 精确闭合轮廓坐标
   ↓
确定性组装 assemble()     骨架 + 各轮廓 points → 完整 RawGcadDocument（与旧 llm_raw 同构）
   ↓
_repair_skeleton()         骨架通用修复（见 §2.3）
```

**Agent A prompt 约束**（放"产生参数的层"）：
- profiles 必须声明完整参数集（disc: 外径/中心孔/轴厚/轮毂半厚/轮缘半厚/圆角；slot: 齿数/槽数/槽深/喉宽/neck/lobe/bottom 半宽/齿面角/圆角）。
- **HARD CONSTRAINT**：`bottom_half_width ≥ 3.5`（保证 root ≥ 2）。
- 接线规则：composition op（circular_pattern/boolean_cut/union/place）必须在 `__assembly__` 组件；boolean 恰好 2 输入；close_profile 紧跟 add_polyline。
- 输出名/类型契约：create_2d_sketch→`sketch`、add_polyline/close_profile/fillet_sketch→`profile`、extrude/revolve/pattern/boolean→`body`（type=solid，非 solid_array）。

**Agent B 轮廓不变式**（继承 `param_prompts.py` 的 DISC/SLOT_PROFILE_RULES + 数值不变式）：
- 榫槽：root 半宽 = `bottom_half_width − 1.5`（与 SLOT_PROFILE_RULES 自洽）；每侧 `2+4×teeth+3` 点；对称；lobe 从外到内递减；任意相邻点 ≥1.5mm；禁重合点。
- 盘体：12 点闭合 R-Z；hub→web→rim 三段；禁相邻重合点；最短边 ≥1.5mm。

## 四、核心架构决策（用户理念，务必遵循）

1. **全 LLM**：不用确定性校验器/确定性组装/硬编码模板（会不断膨胀难维护、变成"LLM 套壳填参"）。生成全 LLM；校验（通用几何质量门）与执行（Compiler）保持确定性——校验不随零件种类膨胀，不算专家系统。
2. **agent + 正确约束**：单 LLM 拆子 agent 减轻压力（实测有效：轮廓 agent 单一任务 → root 100% 稳定）。约束要**放在产生参数的层** + **与继承规则自洽**（教训：root 约束曾与 SLOT_PROFILE_RULES 的 `bottom−1.5` 冲突，导致 LLM 严格遵循原规则生成 root=1.0）。
3. **后训练是根治方向**：当前打地鼠（dialect/接线/输出名逐轮错）根因是**模型未内化领域规则**。后训练（AeroDisk-LLM，LoRA/QLoRA）让模型内化后，prompt 约束 + 骨架修复可逐步退役（避免套壳观感）。
4. **Gen 规范化参数表不需要**（用户明确）。

## 六、当前问题与失败模式（含实验数据）

### 6.1 生成质量

- **D15 单参数批量（仅检查 llm_raw，5 次）**：有效生成 **4/4 全通过**（root≥2、26 点、对称、无短边、lobe 递减）。
- **多参数组合完整 pipeline（5 族，5 次）**：通过率 **20%**。失败模式：MCP 门实体退化/短边（D15/D16/D22）、validation `unknown_op`（D19）、Agent A 骨架异常（D22 另有 governor_stop 图哈希重复）；另一批次 D01 **基础盘被生成榫槽盘**（Agent A 无视"无榫槽"需求）——成功族漂移。
- **对照根因**：旧单 LLM 高通过率 = **硬编码模板假象**（成功任务盘体轮廓是同一套 KT787 坐标，LLM 照抄）。agent 化后 LLM 真正从参数推导 → 暴露未后训练能力（盘体重复点、榫槽短边 1.0mm、lobe 尺寸偏小）。**通过率下降是"从套壳变真建模"，非回归**。
- 约束（禁重合点/最短边 1.5mm）加后通过率仍 20%，成功族漂移——**LLM 概率波动 > 约束收益，单次测试高噪声**。

### 6.2 盘型能力缺口（F17）

- **LLM 不生成孔/环槽 op**：D05（孔盘）生成榫槽盘（无 `cut_circular_hole_pattern`）、D10（环槽盘）pipeline 失败（无 `cut_annular_groove`）。
- 操作库已注册孔/环槽 op，验证规则存在——**是生成层（prompt/未后训练）问题，非执行层**。
- **打孔不需要单独 agent**：孔是参数化 op（count/pcd/dia），Agent A 直接生成 `cut_circular_hole_pattern` 节点即可；`_OP_TO_DIALECT` 需加 `cut_circular_hole_pattern→axisymmetric`。

### 6.3 其他

- 早期任务 L 日志（pipeline_log/tool_calls）不可回溯（运行时未记录；仅 7/70、6/70 为后期实验任务）。
- 6 个任务 canonical_ir 不可生成（4 早期 hash + 2 mon_sweep，均 `root_node` 缺 / `apply_safe_fillet` op 漂移）。

## 七、数据齐全性审计结论

**基础设施能力齐全**（能收集论文要求的全部数据项）：S/Y 元组字段、四类任务构造器、标注、隔离键、32 设计族定义、级联过滤、agent 化生成。

**实际数据远未齐全**（能收集 ≠ 已收集）：
1. **规模差 3-4 数量级**：70 任务 vs 论文 49,920 模型/217,920 任务。**D01-D32 候选未生成**（数据构建本体未启动）。
2. **盘型能力缺口**：仅榫槽盘 + 基础盘。32 族中 20 族（孔/环槽/耦合/复杂轮缘）无法产出。
3. **Rregen 未批量**（2/70）；**早期 L 日志不可回溯**；任务样本演示级（edit 5/repair 21/mcp 135）。
4. **Benchmark**（8 族 40 任务 + 参数扰动/鲁棒性/不可行）未定义。
