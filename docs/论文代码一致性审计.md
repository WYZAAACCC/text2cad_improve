## 三、SER 结构化工程推理（🔴 缺失 / 超前）

- 论文：每个生成样本带七字段 SER（主体区域识别 / 参数归一化 / 特征分解 / 榫槽轮廓构造 / 依赖组织 / 约束检查），且"可由规则、参考 IR 或 CAD 执行结果复核"。
- 代码：**LLM 输出中无任何 SER 字段**。唯一近似是确定性编译中间端（`generative_cad/analysis/` 的 ShapeFacts + planning 诊断，回喂修复 prompt），但那是**程序分析**，不是"模型输出的结构化推理标注"。spatial 前端的 `rationale`/`assumptions` 字段是空间关系说明，与论文 SER 无关。
- 去除 SER 后指标下降（论文 §结果）无法在代码中验证。

**⚠️ 定位澄清（重要）**：SER 是**数据构建阶段的训练标注**，不是运行时 LLM 生成过程的产物——它只在造训练数据时产生、只服务于微调。因此其缺失的根源是"整条数据构建管线不存在"，而非"运行时缺少 SER"；它与 NL2DiskCAD 数据集、AeroDisk-LLM 微调是**同一根子问题**（无数据管线 + 无微调）。论文"去除 SER 后指标下降"是训练数据层面的消融，非运行时行为，无法用现有代码验证。

**结论**：论文"结构化工程推理标注"在代码中无对应物；属于数据构建环节缺失的连带项。

## 三之二、规范化参数表 / 参数归一化（🔴 完全缺失）

- 论文相关主张：
  - 输入形式 `X = (T, Pe, Ch, Cs, O)`，其中 **Pe 为用户明确给出的参数**（规范化参数）
  - NL2DiskCAD 每个样本包含**规范化参数表**（输出要素之一）
  - SER 第 2 步"**提取参数并统一单位**"（参数归一化）
  - 评价指标参数识别准确率 `AP` 基于"参考参数集合 Pr vs 模型提取参数集合 Pg"
- 代码实际：
  - **不存在独立的"规范化参数表"数据结构**（全库 grep `parameter_table`/`NormalizedParam` = 0）
  - **没有"从需求提取参数 → 统一单位/补默认/派生参数 → 生成参数表"的显式环节**；L2 LLM 直接把参数数值内联进 Disk-G-CAD 的 `nodes[].params`（单位固定 mm，无单位转换逻辑）
  - 唯一近似物：
    - `authoring/design_intent_extractor.py`：**极少数英文正则的兜底**（外径/高度/长度、孔数/肋数等），注释自述 "pragmatic fallback — a future version may use LLM-based extraction"，不处理中文领域术语、不产出参数表
    - `authoring/spatial/answer_normalizer.py`：**空间关系答案**规范化（SpatialRelationDraft 约束），与 CAD 参数无关
  - 评价所需的"模型提取参数集合 Pg"无从得到（无提取机制）

**结论**：论文"规范化参数表/参数归一化"是独立于 Disk-G-CAD 的中间产物，代码中无实现；参数由 LLM 直接内联，缺少可审计的参数表与单位统一环节。

## 四、Feature Graph / Disk-G-CAD 分层（🟠 措辞差异）

| 论文声称 | 代码实际 |
|---|---|
| Feature Graph 与 Disk-G-CAD 是**两个分层对象**；Disk-G-CAD 是 Feature Graph 的**领域化执行文档**（隐含先后/细化关系） | **一份 `RawGcadDocument` 图+文档合一**；无独立 Feature Graph 对象、无"Feature Graph → Disk-G-CAD"转换步骤；`canonicalize` 是文档内 raw→canonical（类型解析/producer_node/postconditions 注入） |

**结论**：论文的理想两层架构在代码中是"一份 JSON 的两个视角/阶段"。

## 七、多智能体（🟠 措辞差异）

- 论文：pre-checker / generator / runner / corrector / post-processing 五类智能体协同，共享统一错误对象。
- 代码：**单一 LLM + 确定性阶段控制流**——同一 `DeepSeekToolCaller` 在确定性循环中反复调用。角色映射到同一程序的不同阶段：

| 论文智能体 | 代码对应 |
|---|---|
| pre-checker | L1 路由（能力边界判定）+ `design_intent_extractor` + spatial 澄清循环 |
| generator | L2 authoring（`generate_raw_gcad_document` 或分步 `FeatureSequenceDraft`+`NodeParamsDraft`） |
| runner | `run_canonical_gcad`（确定性执行） |
| corrector | `repair_kernel`（确定性 autofix + LLM `RepairPatchV2` 双环） |
| post-processing | `geometry_postcheck` + `inspection_validation`（确定性） |

- **真实存在的核心机制**：`run_generation_loop` 双环修复（validation 环 + runtime 环）、`RepairStateV2`（max_attempts=3、防循环哈希）、`QualityVector` 严格改善验收、runtime 失败分类器（fail-closed）。

**结论**：修复机制真实且强；"多智能体"表述需改为"角色分工/确定性工作流协调"。

**结论**：MCP 层"已实现并验证"但"未接入生产"；论文若声称"系统通过 MCP 检查"需先接入。

## 十、参数再生（🟡 简化）

- 论文：`Vregen = VΔP ∪ Descendants(VΔP)`，**仅重建受影响节点及其后继子图**；800 组扰动，再生成功率 95.8%。

- 论文量化结果（单参数 98.1%、双参数 96.7%、3-5 参数 93.8%、跨特征 87.5%）无数值支撑。

**结论**：功能有实验实现，但"局部重建"优化与实验数据缺失。
