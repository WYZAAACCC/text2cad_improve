⚠ 更正声明 · 2026-09-15 · 本文档部分结论已被证伪，请勿引用

L4「完全无人」是错的。「应力场 → 参数化特征参数灵敏度」在古典优化界已完成：Choi & Chang 1994（design velocity field）、Hardee et al. 1999（Pro/E 参数 → stress DSA）、Robinson et al. 2012（adjoint × design velocity = ∂J/∂CAD 参数）、Verstraete et al. ASME GT2017-65005（涡轮，max von Mises 为目标）。「选哪个特征」也有：Robinson, Armstrong & Chua, SMO 46(3), 2012。

LLM 侧同样有人做。FRAME（OpenReview 2TdYc5V4jU）：VLM 读 FEA 云图 → 提出具名几何修改 → 更新 CSG → 重算。商用侧 Synera AutoRib（主应力图 → 参数化 rib 网络）、Ansys RBF Morph BGM（von Mises 直接驱动表面 morphing）、Dassault 3DEXPERIENCE（IF max stress > yield THEN strengthen 规则驱动参数）。

同构不变性不能解释 53%。两条榫齿带半径差 70 mm，无任何对称或重编号可互换，那是语义/知识错误而非 shortcut。四类「同构变换」中单位制切换属协变而非不变，概念错误。

论文定位 · 涡轮盘自动建模与仿真智能体 · 2026-09-14 · 第四版（终）

给智能体它自己推不出来的东西

四轮调研收敛到一个反直觉的结论：让 LLM 看应力云图去决定改哪里，已经被一篇有对照实验的工作证伪了 （p = 0.382，打不过一个确定性热点启发式）。而这恰恰指明了出路—— 闭环的瓶颈不是给模型更多信息，而是给它推不出来的信息：特征灵敏度，与反馈的可信度。

§0结论先行

反馈的语义分辨率决定闭环能否收敛。
而分辨率不能再靠"让模型多看图"提高。

把现有工作按反馈信号的语义分辨率排开，空白一目了然： L0（跑通/报错）与 L1（全场→标量）已经拥挤； L2（全场→网格单元）是经典形状优化的地盘，早已解决； L3（全场→定位到参数化特征）有人试过并且失败了； L4（梯度/特征灵敏度）完全无人。 而 L3 的失败方式很说明问题——不是模型不够强，是它被要求从一张图里反推一个它算不出来的量。

被证伪的那条路线。IterSIMP-σ（arXiv 2605.19110）让多模态 LLM 读 density + von Mises 渲染图， 提出"空间干预"（软密度种子）。结果：几何均值低 1.9%，但不显著（W = 33, 双侧 p = 0.382）， 而确定性 exact-hotspot 种子打平。作者的结论原话是：这支持它作为 inspectable design-automation framework，但 「尚不能作为 LLM 视觉推理改善应力约束优化的证据」。

这条结论的价值在于它反向定义了机会：既然"看图提建议"打不过启发式， 那么有增量的方向就只能是给智能体它自己推不出来的量—— 特征灵敏度、adjoint 场、以及反馈的可信度标注。

第一句，来自 IterSIMP-σ §7.1——作者自己承认没做那件经典方法会做的事：

「This is a deliberate architectural choice, not an equivalence claim… The SIMP density update receives no gradient information about the stress field: sensitivities ∂σvm/∂ρe are never computed… In classical stress-constrained formulations—P-norm penalty, augmented Lagrangian, or q-p-relaxation— the stress constraint enters the Lagrangian directly, and adjoint analysis provides element-wise stress sensitivity to guide the density update.」

第二句，来自 LLM-IDA 的摩托车车架案例（17 页全文，HEP 镜像）—— 最接近的竞争者在正文里承认拓扑命名问题做不到：

Therefore, a manual step is required to select the load points… If future research enables the identification and selection of the simulation load and constraint points, LLM-IDA can achieve full-process automation.」

也就是说：一个方向自己承认绕开了梯度，另一个方向自己承认识别不了载荷点。 这两句合起来，就是本文的问题陈述——不需要你再论证。

CAD 侧：Feature-mapping optimization（Shannon / Robinson 等，Queen's University Belfast 2023） 用与商用 CAD 的拉伸/扫掠特征模板对应的映射函数，解析可微； Parametric Design Velocities（Robinson 组）把 adjoint 表面灵敏度与 「CAD 参数变化引起的边界法向移动」链接，直接给出目标函数对 CAD 参数的梯度。

§2闭环在哪里断——五类硬证据

这些是"为什么需要你这套东西"的论据，全部有出处。

  1. 首轮几乎全军覆没，收益靠堆算力。Self-Improving CAD / Hephaestus-CCX（2605.17448）： Codex 与 Claude Code 的 400 次首轮尝试零严格通过；最长反馈循环把 GPT-5.5 从 38.8% 拉到 60.5% （9/50 通过），代价是 68 min/件、总计 359,525 s。作者明说 「expanded reasoning effort does not improve performance monotonically」。
  2. 迭代收益按幂律枯竭。Frontier-Eng（2604.12290）：改善频率按 t⁻¹（R² = 0.84）、 改善幅度按 k⁻¹ 衰减，中位数每任务只有 7 次改善，50–100 轮后趋零。等预算下 depth 完胜 width。
  3. 迭代越多越不稳定。Physics-in-the-Loop（2605.19717）§9.2 自陈原话： 「with more iterations, the results tend to become more unstable. Future work could focus on detecting stopping criteria when a CAD design becomes unrecoverable.」 单次迭代耗时 28.7 ± 36.9 s——方差大于均值。 这正是你的验证层要回答的问题。
  4. 失败模式振荡而非收敛。The Observability Gap（2603.26942，CHI 2026）： output-only 反馈下 0% 全场景成功率，机制是 「correcting one visible symptom repeatedly introduced a complementary failure, preventing convergence」， 形式化为 feedback paradox。
  5. 奖励信号本身没有区分度。Embodied CAD（2606.31252）：18,335 个 candidate group 中 skip-update 率 68.3%，因为"候选都可解析可执行但组内奖励相同"。 其结论「solver feedback is necessary but not sufficient」可以直接引用。
一个必须更正的常见误解

Embodied CAD 用的不是物理求解器。它用的是 CAD 几何内核（FreeCAD）—— 无载荷、无应力、无 FEM。它的 GRPO 奖励是 R_format + R_policy + R_exec， 即解析成功 / 技能匹配 / 执行成功，不是物理验证。 引用时不要写成"solver-grounded"。

§4四个创新点

C-A · 最强

把特征灵敏度送进智能体环路

L4 是唯一完全空白的一档，而且它的两侧都已经成熟： 仿真侧 SIMP 本来就在算 adjoint，CAD 侧 feature-mapping + Parametric Design Velocities 已经给出目标对特征参数的解析梯度。缺的只是把它们接到智能体上。

这条路线的正当性还有一条反面论据支撑：IterSIMP-σ 证明了"从渲染图反推干预"不显著（p = 0.382）。 你要做的不是给模型更强的推理，而是给它一个它算不出来的量。

为什么它天然是你的 · 特征灵敏度必须挂在命名的特征参数上才有意义—— 「σ 对 rim_junc 圆角半径的灵敏度」要求 rim_junc 在两次迭代间是同一个实体。 没有 C1，这个量无处可挂。
直接对照 · 与 ANOVA 归因（IPMSM 那篇用的）对比；与"原始 FEA 输出丢给 LLM"对比（KSME-A 实测：不行，ANOVA 处理后才行）。

一个必须知道的新威胁：ShapeBench（2605.20763，Stanford，103 个 ASO 任务）。 它已经把 E.1 Adjoint (IPOPT): Exact/analytical gradient-based（CasADi + AeroSandbox） 作为 baseline 套件的一项，与三个 LLM 优化器在同一批任务、同一预算度量下头对头对打。 所以「adjoint 对比 LLM」这件事本身已经有人做了。

但它做的不是同一件事：它把 adjoint 当作一个独立的优化基线来跑， 没有把 adjoint 场放进 LLM 的 context 作为决策依据——L4 空白依旧。 它的 two-stage Diagnostic Suite 也只在诊断 surrogate exploitation（逐字证据：DrivAerStar 的 「13 of the 20 total parameters… pushed to their bounds for the converged best designs across all methods, indicating that this convergence pattern is a landscape property of the surrogate」）， 不把诊断结果作为 accept/reject 门。

战略含义：既然梯度法已经是一个强基线，你的立场必须是互补而非竞争—— 搜索交给梯度法，LLM 负责语义层（哪个命名特征、该动哪张面、这条结果可不可信）。 这与下面的挑战二（不要声称省预算）是同一个立场的两面。

C-B · 次强

反馈可信度：区分真实设计改善与数值假象

检索确认：没有一篇用「同一网格」或「网格收敛性研究」作为改进验证的协议。零命中。 而现有工作里假象是被记录在案的：

  • Self-Improving CAD 的九例 pass-flip 归因分析里，四类修复中有两类是假象—— 「mesh-sensitive geometry simplification」（把加载路径简化、网格变好，被记为设计改善） 与 「checker-contract repairs」（物理本来就对，只是 metric alias / mass field / selector binding 缺失导致失败）。
  • 唯一认真处理求解器可信度的是 Luo et al.（2608.07978）：Layer 1 = 引擎精度， 10 个回归算例要求 OpenSeesPy 相对误差 < 1%，与独立 ANSYS APDL 比对容差 2–3%。 这是唯一"先证明求解器可信、再信任其反馈"的设计。它同时自曝了自评价循环风险。
  • 可信度阶梯（2608.05179）：Tier III（数值仿真与守恒律）「hard to fake without actually solving the problem」， 而 Tier V（学习型 verifier / 代理奖励）会撞上 reliability cliff， 且「a surrogate's own confidence certifies nothing about the specific instance」。 另有报告指出同模型 verifier 反而让任务成功率回退 8.4 个百分点。

你的对应物 · 常应力分片试验、故意错 LKEY 的正对照（4.6 倍应力）、 近零载荷对照（1124.595 vs 1123.468 MPa，0.1003%）；并据此推翻了自己的头条数字 （峰值从 r=212.29 迁回 r=60，1553.78 → 1482.90 MPa）。
理论落点 · 这批机制正是 VV&UQ 里的 solution verification（ASME V&V 20 / Oberkampf）， 而 PCMM（Sandia 2007，六要素四级，M/E/R 三分数）与 LLM agent 至今没有交集。

C-C · 便宜的新机制

物理同构不变性检验

IPT（2604.15149，DFKI/TU Darmstadt）：只检查 extensional correctness 的验证器 会主动诱导模型放弃规则学习、转而枚举实例级标签——shortcut 率 GPT-5-nano 36.8%、 GPT-5-mini-high 8.4%，GPT-4o 为 0%，且随算力上升而上升。 对照训练证明因果：extensional 诱导 shortcut，isomorphic 消除 shortcut。

你的 check_criterion 是纯 extensional 验证器——这解释了你测到的 53%。 而「物理设计的同构变换」从未被定义过。你的候选集自动可生成： 60 重周期扇区旋转、榫槽特征重编号、单位制切换（代码里已有 mm-N-t-s 约定）、网格节点重排。 extensional 通过率与 isomorphic 存活率之差就是 shortcut 率。

C-D · 使能前提

溯源锚定的实体身份

不单独作为卖点，而是 C-A 与 C-B 的共同前提——这样写更有力： 梯度要挂在命名特征上（C-A），可信度要锚到具体实体上（C-B），二者都要求跨 revision 的实体同一性。 而 COMSOL-MCP（Neurocomputing 2026）在 future work 里写的就是 spatial grounding + topology-aware entity selection，并给出痛点原话： 「语法合法的 API 调用仍可能生成物理上无效的模型」。

§5两个必须在论文里正面回应的挑战

挑战一 · 静态判据注定被追上

Verification Horizon（2606.26300，Qwen Team）：没有任何固定 reward function 能在策略能力增长时保持有效 ——验证必须与生成器共同演化。三条性质不可兼得：scalability / faithfulness / robustness。

回应：判据由 agent 声明、天然可版本化，把"判据演化"做成设计要求； 并用 C-C 的同构不变性作为不依赖判据内容的独立检验。

挑战二 · 别提「省仿真预算」，除非打赢两个对照

When Is an LLM Worth It for HPO?（2606.21641）：budget-matched 下给经典搜索同样的 warm-start， LLM 提议不带来任何 sample efficiency 优势（TPE/GP-BO 约 12 次评估后追平，40 次反超）。 SimulCost（2603.20253，ICML）：LLM agent 比传统 scanning 慢 1.5–2.5×。

回应：把 LLM 定位在语义工作（选面、定载荷、判读、写判据、读灵敏度）， 数值优化交给确定性方法。另可正面借用 Jadhav 的对照：LLM ≤25 次 FEM vs NSGA-II 50,000–100,000 次——但要说明这是不同问题类别。

挑战三 · 别落回被证伪的路线

IterSIMP-σ 的 p = 0.382 是一条警戒线。任何"我们的 agent 看了应力图/云图/渲染图然后提出设计建议" 的写法，都会直接撞上这个对照。把 C-A 放在最前面就是为了避开这一条。

中心论点

设计闭环的瓶颈是反馈的语义分辨率。提高分辨率不能靠给模型更多图 （已被证伪），只能靠给它推不出来的量：目标对命名特征参数的灵敏度， 以及这条反馈本身的可信度。二者都要求同一件前提——跨 revision 稳定的命名实体。

贡献声明

  1. 提出反馈语义分辨率阶梯（L0–L4），据此定位出现有工作的两个空白：L3 已尝试但失败、L4 完全无人。
  2. 把特征灵敏度（adjoint / feature-mapping / Parametric Design Velocities） 首次接入智能体设计环，并证明它可以挂在跨 revision 稳定的命名特征上；给出与 ANOVA 归因的对照。
  3. 提出反馈可信度层：用分片试验与正负对照区分真实设计改善与数值假象， 并以三态判决词汇表（刻意不含 verified）约束结论强度；该层推翻了作者自身的头条结果。
  4. 给出物理同构不变性检验，把 IPT 的不变性原理首次落地到物理设计域，并实测 shortcut 率。

章节骨架

1 · Introduction 闭环已能跑通但收益按幂律枯竭、迭代越多越不稳定、奖励无区分度；IterSIMP-σ 的 p=0.382 作为转折点。
2 · Related Work 按 §2 的分辨率阶梯组织，而不是按 solver 或按模型组织——这本身就是贡献。
3 · System 阶段 DAG、溯源锚定身份链路、判据契约反转、运行时强制不变量。
4 · Feature Sensitivity → C-A 灵敏度如何挂到命名特征；与 ANOVA / 标量反馈 / 渲染图三种基线的对照。
5 · Feedback Credibility → C-B 分片试验与对照设计；三态词汇表与「为什么没有 verified」；被推翻的自身结论；与 VV&UQ / PCMM 的对接。
6 · Isomorphic Invariance → C-C 四类物理同构变换；extensional 通过率 vs isomorphic 存活率；53% 的重新解释。
7 · The Loop → C-D 溯源稳定的再参数化；迭代轨迹；与随机 / 模板 / 贝叶斯优化对照（须先战胜 HPO 与 SimulCost 两个反向对照）。
8 · Discussion · 9 · Limitations 判据如何随能力演化；为什么把 LLM 定位在语义而非数值；限制如实写。

三个工程风险，现在就要处理

① 哈希链的尾部截断不可检测。前向 hash chain 只能发现内部删除； session-close sentinel 会被它要警示的那次截断一起删掉。必须周期性把 chain head 发布到 off-host。

② 记忆的作用域污染。verification gap 综述的原话： 「目前没有任何记忆库能区分一条被验证过的教训和一条侥幸的教训」。 你的三态词汇表正是这句话的定义性解答——unverified 永远不进经验库。值得单独成节。

③ 停止判据。Physics-in-the-Loop 自陈「迭代越多越不稳定……未来工作可关注何时判定一个 CAD 设计已不可恢复」—— 这是一个被明确留白的开放问题，而你的验真层加可信度标注正好是对它的回答。建议写进 Discussion。

最后一条提醒

这批综述（Zeman et al. AEI 2026；ACM CSUR 58(9):225）列的开放问题是安全、可信、数据、成本这类外围问题， 没有一篇把"仿真反馈如何落到具体几何特征"列为开放问题。 这对你既是机会也是风险——你需要自己把这个 gap 立起来， 而 §2 的分辨率阶梯就是用来做这件事的框架。
